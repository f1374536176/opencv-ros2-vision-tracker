# 轨迹追踪

> 目标：在 HSV 颜色追踪的基础上，用 `deque` 滑动窗口缓存目标中心点，画出运动轨迹。  
> 环境：Ubuntu 24.04 + OpenCV 4.8 + C++  
> 相关：HSV 颜色追踪见 [hsv_basic.md](hsv_basic.md)，ROS2 节点版本见 [ros2_node.md](ros2_node.md)。

---

## 1. 核心原理

### 1.1 轨迹是什么

轨迹不是图像上的“线”，而是**一串历史中心点**。每一帧算出目标中心 `center`，存进一个固定长度的容器；每帧重新遍历容器，把相邻两点用 `line` 连起来，就形成了"轨迹"。旧点被淘汰，新点补进来，视觉上就是一条跟着目标流动的尾巴。

关键点：**画面是每帧重绘的，轨迹线不是“保留”在屏幕上的，而是每帧根据容器里的点重新画一遍。** 容器空了，线自然就没了。

### 1.2 为什么用 deque 而不是 vector

`trajectory` 是一个**滑动窗口**：新点从尾部进，旧点从头部出，长度固定为 30。

| 操作 | `std::deque` | `std::vector` |
|------|-------------|---------------|
| 尾部插入 `push_back` | O(1) | O(1)，均摊 |
| 头部删除 `pop_front` | O(1)，只改标记 | **O(n)**，需移动后续所有元素 |
| 内存分布 | 分段连续（多个内存块 + 中央调度） | 整块连续 |
| 随机访问 `[]` | O(1) | O(1) |

`vector` 没有 `pop_front`，只能用 `erase(begin())` 或 `v = vector(v.begin()+1, v.end())`，两者都是 O(n)。30 个点看不出差别，但高帧率视频里每帧都做一次 O(n) 搬运，积累起来就是卡顿。

`deque` 的逻辑是：**淘汰头部只改标记，不搬数据。** 新数据从尾部进，旧数据从头部丢，两块内存互不干扰。这是它做滑动窗口的核心优势。

### 1.3 处理流程

```
读取帧 → 颜色识别得到中心点 center
    ↓
trajectory.push_back(center)
    ↓
若 size() > 30，trajectory.pop_front()
    ↓
遍历 trajectory，用 line 连接相邻两点
    ↓
显示窗口 + 按键检测（R 清空轨迹）
```

## 2. 关键代码

### 2.1 引入头文件与声明容器

```cpp
#include <deque>

std::deque<Point> trajectory;   // 轨迹仓库，存最近 30 个中心点
```

放在 `main` 外或 `while` 前都可以，只要在检测和画线之间可见。放在 `main` 外是全局变量，放在 `main` 内是局部变量，二选一。

### 2.2 检测到目标时存点

```cpp
if (max_area > 500) {
    // ... 原有画框、画十字代码 ...

    // 把当前中心点存入轨迹仓库
    trajectory.push_back(center);
    if (trajectory.size() > 30) {
        trajectory.pop_front();   // 只保留最近 30 个点
    }
}
```

**只有检测到目标时才存点。** 目标丢失时不做任何操作，队列保持不变。

### 2.3 每帧画线

```cpp
for (size_t i = 1; i < trajectory.size(); i++) {
    line(frame, trajectory[i-1], trajectory[i], Scalar(0, 255, 0), 3);
}
```

- `line` 的参数：画布、起点、终点、BGR 颜色、线宽。
- `i` 从 1 开始，因为要访问 `trajectory[i-1]`。
- 这段循环**放在 `if (max_area > 500)` 外面**，只要队列里有历史点，即使当前帧没检测到目标，也会照常画。

### 2.4 R 键清空轨迹

```cpp
int key = waitKey(1);
if (key == 'q') break;
if (key == 'r' || key == 'R') {
    trajectory.clear();
    cout << "轨迹已清空！" << endl;
}
```

`clear()` 只清空容器，不改动其它变量。下一帧遍历时队列为空，画线循环不执行，屏幕上的绿线消失。

## 3. 参数与调参

### 3.1 窗口长度为什么取 30

`trajectory.size() > 30` 里的 30 是**经验值**，决定了轨迹尾部的长度：

| 长度 | 效果 |
|------|------|
| 5–10 | 短尾巴，只反映最近的运动方向 |
| 30 | 适中，能看到一小段历史轨迹 |
| 100+ | 长尾巴，但长时间遮挡后会残留旧线 |

30 帧在 30fps 下大约是 1 秒的历史。想要更长的轨迹，改这个数字即可，但要注意：**长度越长，遮挡或快速移动时残留的旧轨迹越难自然消退。**

### 3.2 轨迹点用的是图像坐标系

`Point center` 的坐标是**图像坐标系**：

- 原点 `(0, 0)` 在画面**左上角**
- X 轴向右
- Y 轴向下
- 单位是像素

如果用这个坐标直接去控制真实小车，**会出问题**。原因见 4.3。

## 4. 踩坑记录

### 4.1 目标从一侧出、另一侧进时轨迹"穿屏"

- **现象**：把物体从画面左边移出，再从右边移入，屏幕上会出现一条横穿画面的绿线。
- **根因**：目标丢失期间队列没清空，旧点在左边缘、新点在右边缘，`for` 循环把这两点直接连了起来。
- **思考**：
  - 画线的本质就是遍历队列、连接相邻点。要断开，就得让"旧轨迹"和"新轨迹"之间有一个**不在同一队列**的边界。
  - 可行方案是：目标从边缘消失时创建新队列，或者用计数器检测"连续丢帧"后清空。
- **鲁棒性改进**：加一个 `int lost_counter`，连续丢失 5 帧才清空队列；只漏一两帧时保留轨迹线，等待目标回来。这样能过滤摄像头瞬间闪烁的干扰。

### 4.2 目标在屏幕外时按 R 的队列照样清空

- **现象**：目标已经飞出画面，此时按 R 键。
- **结果**：`trajectory.clear()` 依然生效，队列被清空。目标移回来后，轨迹从零重新开始画，不会续接之前的线。
- **原理**：`clear()` 直接清空容器数据，和目标是否在画面里无关。

### 4.3 图像坐标不能直接给底盘用

- **现象**：以为把 `center.x`、`center.y` 发给小车就能追物体。
- **根因**：图像坐标系和机器人底盘坐标系不同：
  - 图像：原点左上、Y 向下、像素单位
  - 底盘：通常原点在车体中心、X 向前、Y 向左、米单位
- **结论**：不能直接照搬，严格使用需要坐标变换；简化场景可近似。对于严格使用时至少包括：
  1. 像素 → 物理尺寸的标定（用相机内参）
  2. 图像坐标系 → 相机坐标系的旋转
  3. 相机坐标系 → 底盘坐标系的平移 + 旋转
- **简单情形**：如果摄像头正装在车头、方向与车头一致，二维上可以做简化：图像 X 方向的偏差 → 底盘的转向，目标靠近画面中心 Y 方向 → 底盘前进。但这是工程近似，严格做还要引入机器人的旋转矩阵变换。

### 4.4 deque 遍历时内存不连续

- **现象**：把窗口从 30 改成 3000，观察会不会卡。
- **结论**：实测不卡。原因是：
  - `deque` 是**分段连续**的：多个固定大小的内存块 + 中央调度表。块内连续，块间用指针串联。
  - `for` 循环遍历时，块内指针是顺序的，块间跳一次指针，整体仍是 O(n)。
  - 3000 个 `Point` 每帧遍历一次，对现代 CPU 来说是极小的开销，远小于图像处理本身的成本。

> **对比**：如果是 `std::list`（链表），节点不连续、每次都要跳指针，缓存命中率差，才可能成为瓶颈。`deque` 的块状结构比链表缓存友好得多。

## 5. 验证结果

- 荧光绿目标移动时，屏幕上有连续的绿色轨迹线跟随。
- 目标完全移出视野时，轨迹线停在最后一帧的位置，不清空、不消失。
- 按 `R` 键后绿线立即消失，下一帧目标被检测到时从零开始画。
- 窗口长度 30 帧，约 1 秒历史，视觉效果合适。

## 附：本篇涉及的关键 API

### 容器

| API | 准确签名 / 调用 | 笔记中的用法 | 说明 |
|-----|----------------|-------------|------|
| `std::deque` | `template<class T> class deque;` | `deque<Point> trajectory;` | 双端队列，头尾都 O(1) 插入删除 |
| `deque::push_back` | `void push_back(const T& value);` | `trajectory.push_back(center);` | 尾部插入 |
| `deque::pop_front` | `void pop_front();` | `trajectory.pop_front();` | 头部删除 |
| `deque::size` | `size_type size() const;` | `trajectory.size() > 30` | 当前元素个数 |
| `deque::clear` | `void clear();` | `trajectory.clear();` | 清空所有元素 |
| `deque::operator[]` | `T& operator[](size_type pos);` | `trajectory[i-1]` | 随机访问，O(1) |

### 绘制

| API | 准确签名 / 调用 | 笔记中的用法 | 说明 |
|-----|----------------|-------------|------|
| `line` | `void line(InputOutputArray img, Point pt1, Point pt2, const Scalar& color, int thickness = 1, int lineType = LINE_8, int shift = 0);` | `line(frame, trajectory[i-1], trajectory[i], Scalar(0,255,0), 3);` | 画两点之间的连线 |

### 键盘

| API | 准确签名 / 调用 | 笔记中的用法 | 说明 |
|-----|----------------|-------------|------|
| `waitKey` | `int waitKey(int delay = 0);` | `int key = waitKey(1);` | 返回按下的键，返回值为 int，常与 `char` 比较，实际比较的是 ASCII 码 |
